# Custom Search Engine

A Python-based custom search engine that combines web search, AI-generated answers, conversation memory, query rewriting, result ranking, and source citations.

The application searches the web for relevant information and uses an LLM to generate a concise answer based on the retrieved sources.

---

## Features

- Web search using Tavily
- AI-generated answers using Groq
- Conversation memory
- Intelligent follow-up query rewriting
- Query decomposition for multi-part questions
- Custom search-result ranking
- Duplicate and low-quality result filtering
- Source citations
- Citation validation
- Error handling and graceful API failures
- Interactive command-line interface
- Automated testing with pytest

---

## Architecture

The search engine follows a retrieval-augmented generation (RAG) style architecture.

```text
User Query
    │
    ▼
Query Analysis
    │
    ▼
Conversation Context
    │
    ▼
Query Rewriting
    │
    ▼
Tavily Web Search
    │
    ▼
Result Filtering
    │
    ▼
Custom Result Ranking
    │
    ▼
Top Search Results
    │
    ▼
Groq LLM
    │
    ▼
AI-Generated Answer
    │
    ▼
Citation Validation
    │
    ▼
Final Answer + Sources
```

## How It Works

### 1. User Query
The user enters a question through the command-line interface.  
Example: Search > What is Python?  
The query is then passed through the search pipeline.

### 2. Query Analysis
The application cleans and analyzes the user's query. For multi-part questions, it can identify separate questions when appropriate.  
For example: "Why is the sky blue and does it look different on Mars?"  
can be processed as two related search queries.  
However, the system avoids incorrectly splitting questions such as:  
"What are Python and Java used for?"  
which should remain a single search query.

### 3. Conversation-Aware Query Rewriting
The search engine maintains conversation history so that follow-up questions can use previous context.  
For example:  
#### User: What is Python?  
#### User: Who created it?  
The system can rewrite the second question into a standalone search query:  
Who created the Python programming language?  
This allows the search engine to retrieve relevant sources even when the user uses references such as:  
- it
- they
- this
- that
- the previous one

### 4. Web Search
The rewritten query is sent to Tavily.  
The search engine retrieves multiple results containing information such as:  
- Title
- URL
- Content
- Relevance score

These results are then passed to the ranking system.  

### 5. Result Filtering and Ranking
The ranking system filters out poor-quality results before selecting the sources used by the AI.  
A result must contain:
- A valid URL
- A title
- Sufficient content

The ranking system then considers:
- Tavily relevance score
- Query words appearing in the title
- Query words appearing in the content
- Duplicate URLs
- Duplicate domains  

The highest-ranked results are selected as context for the LLM. 

### 6. AI Answer Generation
The selected search results are passed to a Groq-hosted LLM.  
The model generates an answer based on the retrieved information.  
For example:  
Python is a high-level programming language used for web development, automation, data analysis, and more. [1]

### 7. Citation Validation
The application checks whether citations generated by the LLM correspond to actual retrieved sources.  
For example, if the search engine retrieved three sources:  
[1]  
[2]  
[3]  
then a generated citation such as:  
[7]
is considered invalid.  
Invalid citations can be removed before the final answer is displayed.

### 8. Error Handling
The application is designed to handle common failures gracefully.  
Examples include:
- No search results
- Invalid search results
- Search API errors
- LLM errors
- Empty LLM responses
- Invalid citations

Instead of terminating with an unhandled traceback, the application provides an appropriate error message and continues running where possible.

## Installation

### 1. Clone the Repository
git clone https://github.com/nehal216/custom-search-engine.git  
- Navigate into the project directory:  
cd custom_search_engine

### 2. Create a Virtual Environment
- Create a Python virtual environment:  
python -m venv venv  
- Activate it on Windows PowerShell:  
.\venv\Scripts\Activate.ps1  
- The terminal should then display:  
(venv) PS C:\custom_search_engine>

### 3. Install Dependencies
- Install the required packages:  
pip install -r requirements.txt

## API Keys

The application requires API keys for:
- Tavily
- Groq

Create a .env file in the project root:  
- TAVILY_API_KEY=your_tavily_api_key
- GROQ_API_KEY=your_groq_api_key

The application loads these variables using environment configuration.

### Security
- Never commit your .env file to GitHub.
- The .env file should be included in .gitignore.

Example:  
- .env  
- venv/
- __pycache__/
- .pytest_cache/
- *.pyc

## Running the Application  

- Make sure the virtual environment is activated.
- Run: python main.py  

The application will display:
```text
====================================================
                CUSTOM SEARCH ENGINE    
====================================================            

Search the web and get AI-generated answers.  
Type 'help' for commands or 'exit' to quit.  

Search >  
```

### Example Usage

- Basic Search:    
Search > What is Python?  
The application searches the web and generates an AI-powered answer using the retrieved sources.  

- Follow-Up Search:  
Search > What is Python?  
Search > Who created it?  
The second query uses the conversation context to understand that "it" refers to Python.  
The system can rewrite it into:  
Who created the Python programming language?

- Multiple-Topic Search:  
Search > What are Python and Java used for?  
The search engine can recognize this as a single query instead of incorrectly splitting it into unrelated searches.

- Commands:  
--- Display the available commands:  
Search > help  
--- Clear the current conversation:  
Search > clear  
--- Exit the application:  
Search > exit

## key Components

### main.py

The main entry point of the application.  
It manages:
- User interaction
- Search workflow
- Conversation history
- Result processing
- Answer generation
- Citation validation
- CLI commands  

### search.py

- Handles web search using the Tavily API.
- Responsible for retrieving search results and handling search-related errors.

### query.py

Handles query processing.  
- Cleaning queries
- Breaking down appropriate multi-part questions
- Rewriting follow-up questions using conversation context  

### ranking.py

Handles search-result quality and ranking. 
- Filtering invalid results
- Extracting domains
- Calculating custom relevance scores
- Removing duplicate URLs
- Removing duplicate domains
- Selecting the highest-ranked results  

### llm.py

Handles interaction with the Groq API.
- Generating AI answers
- Rewriting conversational queries
- Handling LLM errors
- Handling empty responses  

### conversation.py

- Maintains the conversation history.  
- It allows the application to understand follow-up questions that depend on previous queries.  

### validation.py

Handles citation validation.  
- Extracts citations from generated answers
- Checks whether citations correspond to available sources
- Identifies invalid citations
- Removes invalid citations
